# YZI IMOB — Visual Language v1 (FOUNDATION)

Fonte oficial da identidade visual do YZI IMOB. Responde apenas **como o YZI deve parecer e ser percebido** — não desenha telas, React, componentes nem design system. Nenhum wireframe pode ser produzido sem obedecer a esta linguagem.

## Entradas LOCKED (não alterar)
Runtime Architecture · Context Builder · Capability Graph · Product Operating Surface · UX Composition · Operating Surface Navigation v2 · Workspace Architecture v1. Esta linguagem se apoia nelas sem modificá-las.

## 1. Categoria do produto
O YZI IMOB é um **AI Workspace**. Não é CRM, ERP, Dashboard nem SaaS genérico. Essa decisão orienta toda a evolução visual.

## 2. Sensação do produto
**Deve transmitir:** calma · precisão · inteligência · confiança · foco · sofisticação.
**Nunca transmitir:** excesso de informação · visual gamer · excesso de glow · SaaS genérico · template pronto · estética "Lovable".

## 3. Hierarquia visual
Apenas três níveis de atenção. Nada compete com o primário.
- **Primário:** decisão principal · ação principal.
- **Secundário:** contexto · justificativa · recommendation · confidence.
- **Terciário:** detalhes · histórico · evidence · logs.

## 4. Tipografia
Princípios (sem escolher fonte, sem CSS): tipografia dominante · poucos pesos · títulos fortes · leitura confortável · espaçamento generoso.

## 5. Cores
Filosofia (sem definir paleta): neutros dominam · cor tem significado · nenhuma cor é decorativa · poucos acentos · contraste elegante. Regra central: **menos cor produz mais foco**.

## 6. Espaçamento
Muito espaço negativo · poucos elementos simultâneos · baixa densidade visual · respiro entre blocos.

## 7. Cards
Card existe **apenas** quando representa um objeto operacional. Nunca usar card só para preencher layout. Preferir: painéis · listas · canvas · timelines · workspaces.

## 8. Ícones
Ícones maiores · poucos ícones · um significado claro · nunca competir com a tipografia.

## 9. YZI — dois modos
São **experiências diferentes**, nunca sobrepostas:
- **Inspector (contextual):** relaciona-se apenas ao item selecionado.
- **Workspace Conversacional:** tela própria da YZI, sem competir com o Inspector.

## 10. Workspace Lifecycle
Todos os Workspaces seguem o mesmo ciclo — padrão visual do produto inteiro:
```
Selecionar → Preparar → Executar → Revisar → Aprovar → Finalizar
```
Equivalente:
```
Usuário inicia → YZI trabalha → Resultado → Humano decide
```

## 11. Workspace States
Todo Workspace declara seu estado. Estados oficiais (fechados sem decisão arquitetural):
Empty · Preparing · Working · Waiting · Review · Approved · Error.
